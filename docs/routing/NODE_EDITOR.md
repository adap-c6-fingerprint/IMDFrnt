# 길찾기 노드 편집

최신 작업: [#17](https://github.com/adap-c6-fingerprint/IMDFrnt/issues/17), `feat/#17-command-node-export` (기존 `feat/routing-node-editor`에서 이어짐). 기존 IMDF 태깅 앱의 `CanvasView`, 도면 좌표 변환, 확대·이동, 실행취소, `.imdfrnt` 저장·자동 저장을 재사용한다. 길찾기 그래프는 IMDF 태깅 결과와 별도로 보관한다.

## 사용 순서

1. `IMDF 불러오기…`(⌘⇧I)에서 완성된 IMDF ZIP 또는 폴더를 선택한다. 폴더 안의 `manifest.json`이나 `level.geojson`도 선택할 수 있다. SVG·이미지를 먼저 열 필요가 없다.
2. IMDF의 층 UUID·ordinal·이름과 층별 공간을 자동으로 가져오고 노드 편집 화면으로 이동한다. 왼쪽 층 셀의 텍스트나 여백을 클릭해 작업할 층을 선택한다. 층 삭제는 셀을 우클릭한 뒤 빨간 `층 삭제`에서 요청하며, 층 이름·노드 수·연결 삭제 범위를 안내하는 알림에서 확인해야 실행된다. 취소하면 데이터를 유지하고 삭제 후에는 ⌘Z로 복원할 수 있다. 다중 건물을 지원하며 서로 다른 건물의 동일 ordinal은 허용한다. 층 식별에는 고유한 UUID인 `level_id`를 사용한다.
3. level·unit·section·fixture·detail·opening·amenity의 원본 공간을 표시한다. amenity는 unit 참조로 해당 층에 배치하고, Polygon의 구멍과 MultiPolygon을 유지한다. IMDF의 위경도를 사용하므로 좌표 기준점을 추가할 필요가 없다.
4. **⌘ Command를 누른 채 원하는 빈 위치를 클릭**해 현재 층에 노드를 추가한다. 모든 노드 편집 도구에서 사용할 수 있다. 일반 클릭은 선택이며 노드를 추가하지 않는다. 기존 핀에 ⌘+클릭해도 선택만 하고 중복 생성하지 않는다. 일반 핀 드래그는 위치 이동이고 ⌘+드래그는 추가·이동을 하지 않는다. 핀 지름은 화면 기준 8pt이고 선택해도 커지지 않으며 주변에 파란빛만 표시한다. 핀 아래에는 짧은 UUID를 8pt·50% 불투명도로 연하게 표시하고 접두사가 겹치면 구분되는 길이까지 늘린다. 이름을 입력하면 핀 위에 표시한다. 이름·카테고리는 바로 반영된다. 메타데이터는 JSON 객체로 입력하고 `메타데이터 적용`을 누른다.
5. **⌥ Option을 누르고 핀에서 다른 핀으로 드래그**한다. 선이 포인터를 따라오고 대상 핀에 가까워지면 파란빛으로 표시하며 마우스를 놓으면 연결한다. 출발 핀의 위치는 유지한다. 빈 곳에 놓거나 Escape를 누르면 취소한다. `노드 연결` 도구에서는 Option 없이도 같은 드래그를 사용할 수 있다. 다른 층의 계단·엘리베이터는 이 도구에서 두 핀을 차례로 클릭하고, 층 전환 중 시작 핀을 유지한다. 층간 연결은 양쪽 모두 같은 종류의 계단 또는 엘리베이터여야 한다. 계단은 휠체어 접근 불가로 기록한다. 연결은 양방향이다.
6. 핀 또는 연결선을 선택한 뒤 Delete/Forward Delete를 누르면 확인 알림이 열린다. 빨간 삭제 버튼도 같은 알림을 사용한다. `삭제`로 확정하면 노드 삭제는 연결도 함께 지우고, 연결 삭제는 양 끝 노드를 보존한다. `취소`하면 데이터·선택·실행 취소 기록을 유지한다. ⌘Z / ⌘⇧Z로 되돌리거나 다시 실행한다. 텍스트 편집 중 Delete는 글자만 지운다. 도면 편집의 feature 휴지통·좌표 기준점·임시 문 삭제도 빨간 아이콘과 확인 알림을 사용한다.
7. `작업 저장`(⌘S)으로 지도·층·노드·연결·메타데이터·좌표 변환을 `.imdfrnt`에 저장한다. 30초 자동 저장은 복구본만 갱신하고 명시적으로 저장한 파일은 ⌘S로 갱신한다. 다시 열면 IMDF 노드 편집 화면으로 바로 돌아온다. 새 프로젝트·미저장 확인은 [프로젝트 생성과 저장](../projects/PROJECT_LIFECYCLE.md)을 참고한다.
8. `길찾기 내보내기…`로 전체 층을 `routing-graph.geojson` 한 파일에 내보낸다. GeoJSON은 JSON 형식이며 최상위 `FeatureCollection`에 Point 노드와 LineString 연결이 함께 들어간다. `.imdfrnt`는 편집 작업 저장용이고 클라이언트에 전달하는 파일은 이 GeoJSON이다. 지도(IMDF)와 그래프를 같은 시점의 한 묶음으로 전달하려면 `클라이언트용 묶음 내보내기…`를 쓴다([CLIENT_DATASET.md](CLIENT_DATASET.md), #54).

### 노드와 Unit/Fixture 연결 (#95 / IMD-78)

편집 도구의 **장소 연결** 또는 오른쪽 **노드와 장소 연결하기**를 누른다. 현재 층에서 노드를 클릭한 뒤 Unit/Fixture 면 안쪽을 클릭하면 연결한다. 노드 하나는 여러 장소를 대표할 수 있지만 **장소 하나는 노드 하나에만** 연결된다. 이미 다른 노드에 연결된 장소는 확인 후 교체하며 한 번의 Undo로 복원한다.

- 겹친 Unit/Fixture는 오른쪽 후보에서 직접 고른다. 구멍 내부와 0%로 숨긴 레이어는 선택 대상이 아니다. 선택한 면은 주황 외곽선으로 표시한다.
- 오른쪽 패널에서 선택한 장소의 연결 노드와 선택한 노드의 장소 목록을 확인한다. 연결 해제는 도형·노드를 지우지 않는다. 노드/층 삭제 시 해당 연결도 없어지고 Undo로 돌아온다. Escape·도구/층/프로젝트 전환은 미확정 선택을 초기화한다.
- 원본 IMDF에는 연결 필드를 추가하지 않는다. 프로젝트 노드의 선택적 `featureLinks`가 정본이고 장소별 역조회는 이 정본에서 만든다. 직접 그린 면은 내부 ID를 저장하고 출력 시 그 면의 실제 IMDF UUID를 사용한다. 층 복사에서 관련 UUID가 재발급되면 연결 참조도 따라간다.
- 장소를 삭제/휴지통으로 보낸 뒤 연결이 남아 있으면 목록에 안내한다. 도형을 복원하거나 연결을 해제해야 클라이언트 묶음을 내보낼 수 있다. 일반 IMDF/그래프 단독 내보내기의 기존 검증은 그대로다.
- [클라이언트 묶음](CLIENT_DATASET.md#장소-노드-매핑-95--imd-78)의 별도 JSON으로만 전달한다. 근접 노드를 추정하거나 실제 iOS 경로 탐색 엔진을 변경하지 않는다. iOS 소비자는 이 파일을 읽는 연동이 필요하다.

### 현재 층 레이어 (#92 / IMD-76)

노드 화면 왼쪽 하단에서 **Fixture / Unit / 배경 레이어**의 불투명도를 각각 0~100%로 조절한다. 아래에서부터 배경 → Unit → Fixture → 노드/엣지 순서다. 기본값은 배경 100%·Unit 35%·Fixture 80%이며 0%는 해당 레이어의 면·선 전체를 숨긴다. 노드와 엣지는 항상 위에 남는다.

- Unit·Fixture는 현재 층의 태깅/직접 그린 면과 가져온 IMDF 도형을 표시한다. 구멍과 MultiPolygon을 유지하고 휴지통 도형은 제외한다.
- 배경은 원본 SVG/내장 이미지, 참고 도면과 IMDF의 나머지 타입(level·section·opening 등)이다. 가져온 IMDF의 합성 SVG에서는 Unit·Fixture를 화면에서만 분리해 중복 잔상을 막는다. 일반 SVG에 원래 그려진 벽/가구 선은 배경이므로 함께 숨기려면 배경도 0%로 조절한다.
- 설정은 층별로 프로젝트를 열어 둔 동안만 유지한다. 다른 프로젝트를 열거나 다시 열면 기본값으로 돌아온다. IMDF 편집 화면의 레이어 설정과 독립적이며 프로젝트 파일·원본 도형·좌표·Undo·내보내기를 변경하지 않는다.
- 왼쪽 하단 패널은 캔버스 위에 겹쳐 놓으므로 슬라이더가 캔버스 맞춤/확대·이동 상태를 리셋하지 않는다.

`--routing-selftest`는 층별 상태·데이터 불변·캐시 갱신·가져온 타입 분리 및 작은 Canvas 벡터 이미지로 0/50/100% 합성과 순서를 검사한다. 실제 창의 마우스 조작·좁은 창 배치·PNG/JPG 픽셀 표시는 사람 GUI 검수 대상이다(NSApplication 시작 전 headless ImageRenderer의 CGImage 표시 제한).

### 수직 이동 시설 층별 복제 (신기능 13항, B안)

계단·엘리베이터·에스컬레이터 노드를 선택하면 오른쪽 정보 패널에 `층별 복제`가 나온다. 기준 층에서 한 번 찍은 노드를, 체크한 층(기본 전부)에 **같은 위경도**로 만든다. 층마다 도면 좌표계가 달라도 위경도를 거쳐 그 층 도면 좌표로 옮기며, 새 노드는 대상 층의 UUID를 참조하고 새 노드 UUID를 받는다. 이름·카테고리·메타데이터는 기준 노드를 따른다.

- 같은 시설의 노드는 `verticalGroupID`(선택 항목)로 묶고, 내보내기에서는 노드의 `vertical_group_id`로 나간다. 카테고리가 같아도 묶음이 다르면 연결하지 않는다.
- **엘리베이터**는 같은 묶음에서 층 번호가 이웃한 노드끼리 `elevator` 연결로 잇는다. 일부 층만 운행하면 그 층만 체크해 복제하고, 나중에 다른 층을 더 복제해도 묶음이 이어진다.
- **계단·에스컬레이터**는 노드만 복제하며 층간 연결을 만들지 않는다. `escalator` 카테고리를 추가했다(청록, 저장 식별자 `escalator`). 에스컬레이터는 층간 연결 대상이 아니다.
- 반복 실행해도 같은 층에 중복 노드·연결이 생기지 않는다. 이미 같은 묶음 노드가 있는 층은 건드리지 않고(사용자가 옮긴 위치 유지), 같은 층에 같은 종류 노드가 1 m 안에 사람이 찍어 둔 것이 있으면 새로 만들지 않고 그 노드를 같은 묶음으로만 묶는다.
- 실제 좌표(IMDF 또는 기준점 3쌍)가 없는 층이나 도면 밖으로 떨어지는 층은 건너뛰고 알림에 층 이름을 보인다.
- 복제와 연결은 실행취소 한 번으로 함께 되돌아간다. 복제 뒤 기준 노드를 옮겨도 복제된 노드는 따라가지 않는다. 이전 프로젝트 파일은 그대로 열린다.
## 출입구 노드 자동 배치 (#69)

노드 편집 상단의 `출입구 노드 자동 배치`는 IMDF `opening`의 **길이 기준 중간점**(두 점이면 중점)에 `entrance` 노드를 놓는다. 점 나열 방향·확대율·화면 회전과 무관하다. 원본 opening은 바꾸지 않고 주변 노드와의 연결은 만들지 않는다. 노드의 `sourceOpeningID`로 원본과 짝을 지어 재실행해도 중복되지 않고, 옮기거나 이름을 바꾼 노드는 그대로 둔다. 중앙에 이미 수동 노드가 있거나 geometry가 없음·LineString 아님·좌표 오류·길이 0인 opening은 건너뛰며 사유를 오른쪽 패널에 보인다. 배치한 노드를 지우면 다음 실행에서 다시 만든다.

## 실제 좌표

IMDF 입력은 모든 층에 동일한 북쪽 위 방향 표시 좌표계를 사용한다. 위경도에서 화면 좌표로 변환한 계수를 저장하고 역변환하므로, 별도의 좌표 추정이나 수동 기준점 없이 노드의 WGS 84 좌표를 얻는다. 층별 지도와 변환 계수는 프로젝트에 내장되어 원본 ZIP·폴더를 옮겨도 작업을 다시 열 수 있다. 기존 지도가 있는 상태에서 새 IMDF를 불러오면 별도 프로젝트로 열어 이전 작업 파일을 덮어쓰지 않는다. 아직 도면을 넣지 않은 새 프로젝트에 IMDF를 추가할 때는 해당 프로젝트의 ID·저장 위치를 유지한다.

SVG·PNG·JPG 원본을 쓰는 기존 흐름도 유지한다. `도면 열기…` → `길찾기 노드 편집`에서 시작하고, `클라이언트 층 목록 가져오기…`로 층 정보를 맞춘 뒤 각 층에 도면을 불러온다. 이 흐름은 각 층에서 일직선에 있지 않은 좌표 기준점 3쌍 이상이 필요하다. 원본 도면 교체 시 기존 기준점을 초기화한다.

클라이언트에 전달하는 좌표는 WGS 84 `[경도, 위도]`다. 픽셀 좌표를 경위도로 대체해서 내보내지 않는다. 층 번호는 클라이언트 `Level.ordinal` 규칙을 따른다: 지상 1층 0, 위층 양수, 지하 음수. `level_id`는 클라이언트 층 UUID에 맞춘다. 출력의 `level`은 해당 층의 ordinal 값이며 식별자가 아니다. 다른 건물의 같은 ordinal을 구분할 때도 `level_id`를 사용한다.

## 엣지 그룹 (#88 / IMD-73)

오른쪽 **엣지 그룹**에서 이름을 입력해 그룹을 추가한다. UUID는 생성 시 한 번 발급하고 이름을 수정해도 유지한다.

- **엣지 선택** 도구: 클릭은 단일 선택, Shift 클릭은 추가/해제다. 드래그 사각형과 교차하는 같은 층 엣지를 선택하고 Shift 드래그는 기존 선택에 추가한다. 기존 선택·이동 도구의 핀 이동과 화면 이동은 유지하며 Shift 드래그로 엣지도 선택할 수 있다.
- **배정할 그룹 → 선택 엣지에 적용**으로 일괄 배정한다. 미배정을 적용하면 그룹을 해제한다. 필터로 숨긴 엣지는 화면·히트테스트·사각형/Shift 선택·일괄 배정 대상에서 빠진다.
- **엣지 필터**는 전체/미배정/지정 그룹을 제공한다. 필터는 현재 층에 적용하고 다른 층으로 이어지는 엣지도 해당 층 목록에 보인다. 층간 연결은 목록에서 Shift 클릭으로 다중 선택한다.
- **새 엣지 그룹**은 이후 수동 클릭/Option 드래그로 새로 연결한 엣지에만 적용한다. 이미 존재하는 연결의 그룹은 재연결해도 바뀌지 않는다. 자동 엘리베이터 연결 등 기존 자동화는 그대로다.
- 그룹 삭제는 확인을 거쳐 배정만 해제하며 엣지·노드를 지우지 않는다. 다중 엣지 Delete도 기존 확인 알림을 사용한다. 생성/이름/배정/삭제는 실행취소·다시실행을 지원한다.
- 그룹과 엣지 참조는 공통 프로젝트 안에 저장한다. 층 가져오기는 사용한 그룹만 가져오며 동일 UUID·내용은 재사용한다. 같은 UUID의 이름이 다르면 가져온 그룹에 새 UUID를 주어 양쪽 의미를 보존한다.

길찾기 GeoJSON의 배정된 엣지에만 선택 속성 `properties.group_id`(소문자 UUID)·`properties.group_name`(문자열)을 추가한다. 미배정은 두 속성을 생략한다. 기존 `schema_version: 1`·노드/엣지 필수 속성·IMDF 파일은 변경하지 않으며 클라이언트 묶음도 같은 exporter를 쓴다.

**클라이언트 소비 규칙:** 이어지는 엣지들의 비어 있지 않은 `group_id`가 같으면 한 직진 구간으로 취급한다. 그룹 UUID가 바뀌면 새 안내 판단 지점으로 사용한다. 이름은 표시용이며 그룹 비교 키가 아니다. 미배정끼리 `nil == nil`이라는 이유로 하나의 직진 구간으로 합치지 말고 기존 안내 판단을 유지한다. 층 전환·도착·안전 안내는 그룹 비교만으로 숨기지 않는다. IMDFrnt에는 실제 경로 탐색/음성 길안내 엔진이 없으므로 이 PR은 편집·데이터 전달까지이며 소비 앱의 안내 엔진 연동/실기기 검증은 별도다.

## 클라이언트 계약

기준 소스: [Fingerprint의 최소 길찾기 그래프 fixture](https://github.com/adap-c6-fingerprint/2026-C6-M06-Fingerprint/blob/8274d1d7a82ea39a24dda59d1898fd111831b072/FingerprintTests/Fixtures/minimal-routing-graph.geojson), `feature/indoor-routing-foundation`의 `8274d1d`. 2026-10-07 원격 브랜치를 다시 fetch해 같은 커밋임을 확인했다. 해당 브랜치에는 그래프 로더·경로 탐색 구현이 없고, 이 fixture와 JSON을 읽어 헤더를 확인하는 [테스트](https://github.com/adap-c6-fingerprint/2026-C6-M06-Fingerprint/blob/8274d1d7a82ea39a24dda59d1898fd111831b072/FingerprintTests/RoutingFoundationTests.swift)가 있다. 따라서 아래는 fixture와 일치하는 출력 계약이며 iOS 앱에서 실제 경로 탐색까지 검증한 결과는 아니다. 테스트의 `synthetic-v1`은 샘플의 도면 버전 값이며 사용자 내보내기는 설정한 `layout_version`을 사용한다.

| 대상 | 필드 |
|---|---|
| 파일 | `type: FeatureCollection`, `schema_version: 1`, `layout_version`, `routing_config.hard_search_radius_meters`, `features` |
| 노드 | `type: Feature`, 문자열 `id`, `properties.role: node`, `properties.level`, `geometry.type: Point`, `[경도, 위도]` |
| 연결 | `properties.role: edge`, `from`, `to`, `accessible`, `direction: undirected`, `category`, `geometry.type: LineString` |
| 편집기에서 추가한 노드 속성 | `level_id`, `name`, `category`, `metadata` (JSON 객체) |

노드 기본 카테고리는 `waypoint`이고 `entrance`, `stairs`, `elevator`, `escalator`, `destination`을 편집할 수 있다. 핀 색상은 통로·교차점 파랑, 출입구 초록, 계단 주황, 엘리베이터 보라, 목적지 분홍이며 카테고리 메뉴에도 색상 표시를 함께 제공한다. 알 수 없는 카테고리는 파랑으로 표시하고 원래 문자열을 저장·내보내기에 유지한다. 선택 시 파란 광택과 고정 크기는 모든 카테고리에서 동일하다. 연결 카테고리는 `walkway`, `stairs`, `elevator`다. 노드와 연결 UUID는 생성 시 한 번 발급하고 저장·재열기·반복 내보내기에 유지한다.

자기 자신 연결, 같은 두 노드의 중복 연결, 삭제된 노드 참조를 방지한다. 끊어진 노드와 서로 연결되지 않은 그룹 수를 화면에 표시한다. 잘못된 메타데이터, 중복 층 ID, 유효하지 않은 좌표, 기준점 부족, 잘못된 층간 연결은 내보내기를 막고 이유를 표시한다. ordinal 중복 자체는 차단 조건이 아니며, 같은 건물·ordinal의 Level 면적 겹침은 IMDF 공간 검증에서 별도로 검사한다. 연결되지 않은 그래프는 편집 중일 수 있으므로 경고만 표시한다.

## 저장 호환성

현재 저장 형식은 버전 9이며 기존 v2~v8 파일도 읽을 수 있다. 공통 건물·층·지도/내장 이미지·태깅·좌표 기준·노드·연결·메타데이터는 `buildingProject`에 저장하며 `RoutingGraph`는 호환 뷰다. v8의 엣지 그룹에 이어 v9는 노드의 선택적 `featureLinks`(Unit/Fixture 참조)를 추가한다. 구버전 앱이 장소 연결을 조용히 버리지 않도록 v9 파일을 거절하므로 새 작업은 v9 지원 앱에서 연다. 원본 프로젝트의 별도 백업을 권장한다. 이전과 저장 구조의 자세한 내용은 [건물·Level 관리의 저장 구조](../projects/BUILDING_LEVELS.md#저장-구조)를 참고한다.

## 검사

```sh
./build-app.sh
./IM-DFrnt.app/Contents/MacOS/IM-DFrnt --routing-selftest
./IM-DFrnt.app/Contents/MacOS/IM-DFrnt --selftest
```

노드 자체 검사는 클릭·선택·연결·삭제·이동·층 전환·층간 연결·실행취소·메타데이터·좌표 내보내기·버전 2·3 읽기·이미지 내장 저장·IMDF 공간과 구멍·기준점 없는 좌표 내보내기·IMDF 저장 재열기를 확인한다. 연결 드래그의 미리보기·대상 스냅·빈 곳/자기 자신/삭제된 노드에 놓기·Option+Escape 취소·층 전환 취소·실행취소 및 표시 ID 충돌·저장 유지도 검사한다. 실제 클라이언트 C5 입력은 `--imdf-test-input <IMDF 폴더> --imdf-test-zip <ZIP>`을 추가해 검증한다. 검사 실행은 사용자 자동 저장본을 읽거나 덮어쓰지 않는다.

Command 클릭 검사에는 일반 빈 곳 클릭 방지, 도구별 추가, 기존 핀 선택·중복 방지, 층별 추가, 실행취소·UUID 복원, 도면 밖·가져오기 중 추가 방지가 포함된다. 실제 C5 입력과 함께 `--routing-imdf-test-output <파일.geojson>`을 지정하면 생산 내보내기 코드로 생성한 노드 2개·연결 1개의 검사용 파일을 남긴다. 원본 IMDF 층 정보까지 비교하려면 저장소 루트에서 다음을 실행한다.

```sh
python3 scripts/validate-routing-export.py <파일.geojson> \
  --fixture <클라이언트>/FingerprintTests/Fixtures/minimal-routing-graph.geojson \
  --levels <클라이언트>/Fingerprint/App/Domain/IMDF/C5/IMDFData/level.geojson
```

검사기는 샘플 필수 필드·타입, 양방향 연결 ID 참조, 끝점 좌표, UUID/ordinal 일치를 확인한다. 이름·메타데이터·추가 카테고리는 편집기의 확장 속성이다. 향후 클라이언트 로더가 이 속성을 해석하는지는 로더 구현 후 별도로 확인해야 한다.

삭제 확인 검사에는 엣지 Delete/Forward Delete, 확인 전 상태 유지, 취소, 다른 노드·엣지 보존, 실행 취소/다시 실행, 중복 입력과 텍스트·모달 보호, 알림을 연 대상 ID 유지, 이미 사라진 대상, 프로젝트 전환 및 미확정 알림을 가진 문서의 저장·재열기가 포함된다. 미확정 삭제는 저장 데이터와 실행 취소 기록에 포함하지 않는다.

후속 확장 후보: 연결 중간 점/꺾은선 편집, 연결 위에 찍은 노드로 연결 분할, 일방통행 및 경로 가중치, 길찾기 미리보기. 클라이언트 계약을 확인한 뒤 추가한다.
