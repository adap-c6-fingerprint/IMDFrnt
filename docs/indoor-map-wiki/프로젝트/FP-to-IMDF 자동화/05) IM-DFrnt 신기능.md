- **왜 이 기능이 필요한지부터 정리해 둔다.** 실제 도면의 방은 문 자리에서 벽이 끊겨 있어 닫힌 폴리곤을 만들 수 없다(명세 10-1). 종전 해법은 opening 개체를 다른 feature가 **빌려서**(`BorrowRegistry`) 링을 닫는 것이었는데, 그건 **도면에 문선이 그려져 있을 때** 얘기다. 문이 **열린 상태로** 그려진 도면에는 닫는 데 쓸 선분 자체가 없다 — 문짝과 회전 궤적(호)만 있다. 그래서 사용자가 두 점을 직접 찍어 **없는 선분을 만든다.**
- **찍은 두 점이 곧 opening의 좌표다.** opening의 geometry는 LineString이라 두 점이면 완결된다. `FeatureGroup.closureSegment`에 싣고, `VertexExtractor`가 이 값이 있으면 구성원 대신 이 선분을 쓴다. **구성원(문짝·호)으로 LineString을 만들면 호를 따라 휘어진 엉뚱한 선이 나온다** — 그것들은 문의 *모양*이지 문이 지나는 *자리*가 아니다.

	- **`EditorLayer.baseOpacity`(하위 기본 레이어)를 빌려 쓰지 않았다.** 그 값은 사노 요청으로 20% → 50%가 됐다. 우연히 같았던 수치를 한 곳에 묶으면 한쪽 요구가 바뀔 때 다른 쪽이 조용히 끌려간다. `DoorClosureAppearance.excludedOpacity`로 따로 뒀고 시험으로 못박았다.

### 5-5) 진행률 막대 두 개 (2026-08-26 결정, 구현 전)

**왜 바꾸나.** 지금 진행률은 분모가 개체 수, 분자가 소유된 개체 수 + 보조 제외 수다. 면 단위로 일하게 되면 이 셈이 성립하지 않는다 — **벽선 하나를 옆방과 나눠 쓰는 것이 정상**이라(A13) 개체 기준으로는 끝까지 채워지지 않고, 반대로 다 채워도 남은 일이 있을 수 있다.

#### 5-5-1) 기존 막대 — 개체 기준 (셈하는 방식만 바꾼다)

- **개체 하나가 한 번이라도 처리되면 진행률에 기여한 것으로 본다.** 여러 property type이나 여러 feature가 같은 개체를 공유해도 **한 번만** 센다.
- **막대에 마우스를 올리면 임시 메시지 창을 띄운다**(반투명 검정 창, 올리면 뜨고 내리면 사라진다).
	- 문구: "서로 다른 property type 또는 feature가 동일한 벡터 개체를 공유할 수 있으므로, 진행률을 다 채운 것이 최종 작업 완료를 의미하는 것은 아닙니다."
	- **이 안내가 이 막대의 한계를 그 자리에서 밝히는 장치다.** 숫자만 보면 100%가 곧 완료로 읽히는데, 공유가 정상인 구조에서는 그렇지 않다.

#### 5-5-2) 새 막대 — 다각형 기준

- **분모: 도면의 모든 다각형 수.** 보조 개체(치수선·해치 등)로 만들어지는 다각형까지 **포함한** 수다. 즉 아무것도 제외하지 않은 상태에서 찾을 수 있는 면 전부다.
- **분자를 두 색으로 나눠 표시한다.**
	- ① **제외된 개체 때문에 사라진 다각형** — 보조 개체 제외로 그 면을 이루던 선분이 빠져 더 이상 면이 아니게 된 것
	- ② **태깅한 다각형** — Feature로 저장한 것
- 같은 방식의 임시 메시지 창을 띄운다.
	- 문구: "보조선으로 만들어지는 다각형을 포함하여, 도면의 모든 다각형 수 대비 처리된 다각형 수를 진행률로 표시합니다."
- **이 막대가 실제 작업량을 보여주는 쪽이다.** 자투리 면을 걷어내는 일(보조 개체 제외)과 방을 태깅하는 일이 **둘 다 진척으로 셈된다** — 지금 구조에서는 자투리를 걷어내는 작업이 진행률에 전혀 나타나지 않는다.

### 5-6) 전환 구현 완료 (2026-08-26)

**5-4·5-5의 결정을 전부 반영했다. 화면에서 눈으로 확인해 주시면 완료 처리합니다.**

- **별도 창을 없앴다.** '닫힌 다각형 보기'는 이제 **폴리곤 type 레이어의 기본 화면**이다. 좌측 진입 버튼도 없앴다 — 레이어를 여는 것이 곧 진입이고, 안내 팝업이 그때 한 번 뜬다.
- **캔버스가 두 모드로 갈린다.** 폴리곤 type(unit·footprint·level·venue·section·geofence·fixture)에서는 면을 고르고, LineString(opening)·Point(amenity·anchor) type에서는 **종전 선분 선택이 그대로다.** 선분 선택 코드는 지우지 않았다.
- **포함 / 제외 두 모드**(5-4 1·2번). 포함은 빈 상태에서 더해 가고, 제외는 **전부 고른 상태에서 빼 나간다.** 두 모드 모두 상단바의 **'선택한 다각형 모두 저장'** 하나로 끝난다 — 모드는 선택을 만드는 방법이 다를 뿐, 결과는 같기 때문이다.
	- 상단바에 `고른 수 / 고를 수 있는 수`를 함께 보여준다. **제외 모드 때문에 분모가 필요하다** — 전부 고른 상태에서 빼 나가는데 남은 개수만 보이면 얼마나 뺐는지 알 수 없다.
- **드래그 복수 선택**(5-4 3번). 포함 모드는 더하고, 제외 모드는 뺀다. **클릭과 달리 뒤집지 않는다** — 수십 개가 한꺼번에 뒤집히면 결과를 예측할 수 없다(선분 드래그 선택과 같은 규칙).
- **fixture는 맞닿은 면을 한 feature로 묶는다**(5-4 2번 사노 결정). 변을 나눠 쓰는 면들을 이어 붙여(union-find) 덩어리 하나가 MultiPolygon 하나가 된다. 폴리곤 type은 면 하나가 feature 하나다 — 방 둘이 벽을 나눠 쓴다고 한 방이 되면 안 되기 때문이다.
- **'미그룹만 보기'를 면 단위로도 제공**(5-4 4번). 폴리곤 모드에서는 '저장되지 않은 다각형만 보기'가 되어 이미 저장한 면을 옅게 누른다. **지우지 않고 옅게 하는 이유**는 어디까지 했는지 대조하기 위해서다.
- **곡선만 보기 · 개체 이동 · 겹침 윤곽 표시 · 속성 필터 레이어는 그대로 유지**(5-4 4번). 다만 개체 이동은 **선분 모드에서만** 동작한다 — 면을 고르는 화면에서 드래그는 화면 이동이거나 복수 선택이라 이동이 끼어들 자리가 없다.
- **진행률 막대 둘**(5-5). 개체 기준 막대와 다각형 기준 막대를 위아래로 두고, **각각 마우스를 올리면 반투명 검정 안내 창**이 뜬다(문구는 5-5 원문 그대로). 시스템 툴팁을 쓰지 않은 이유는 뜨기까지 1초 넘게 걸리고 두 줄 넘는 문장이 잘리기 때문이다.
	- 다각형 막대의 **분모는 도면을 열 때 한 번만** 센다(보조 개체로 만들어지는 면 포함). 보조 개체를 빼면 **분모가 줄어드는 것이 아니라 '제외로 사라진 다각형'으로 분자에 얹힌다**(사노 확정).
	- 두 몫을 다른 색으로 그린다 — 태깅한 다각형 / 제외로 사라진 다각형.
- **실행취소 규칙은 종전과 같다**(5-4 7번). 저장은 되돌림 대상이고, **되돌리면 고르던 면도 함께 돌아온다** — 그래야 "저장을 취소했다"가 성립한다. 개별 선택 토글은 종전처럼 되돌림 대상이 아니다(A6).
- **최적화 규칙도 같다**(5-4 7번). 면 찾기는 **레이어를 열 때와 보조 개체 제외가 바뀔 때만** 한다(매 프레임·도면 적재 시점 아님). 드래그 선택은 선택 집합을 **한 번에 대입**한다(`03) 뷰 디버깅.md` 17번의 교훈).
- 새로 만든 것: `UI/ClosedPolygon/PolygonToolbar.swift` · `UI/HoverNote.swift`. 없앤 것: `UI/ClosedPolygon/ClosedPolygonScreen.swift` · `ClosedPolygonPane.swift`(전용 창).
- 검증: `--selftest` **493항목 전부 PASS**(전환분 18항목 신규 — 면 묶기 2 · 모드별 시작 상태 · 제외 모드 클릭 · 드래그 복수 선택 · 저장과 되돌리기 · fixture 묶기 · 진행률 4 등).

## 10. 점 단위 선택과 면 단위 선택의 혼용
> ✅ **구현 완료 — develop 머지** (2026-10-15) — [PR #45](https://github.com/adap-c6-fingerprint/IMDFrnt/pull/45), 이슈 [#21](https://github.com/adap-c6-fingerprint/IMDFrnt/issues/21)(범위 확장). **화면 조작은 아직 직접 확인하지 않았다** (CLI 자체점검만 통과).
> - **점 단위:** 모든 property type 레이어의 기본. 꼭짓점·교점 근처를 누르면 그 점에 붙고, 새 점은 ⌥(Option)+클릭. polygon은 시작점(◎)을 다시 누르거나 Return으로 닫으면 저장, opening은 두 점을 찍으면 바로 저장, Point type은 한 번 찍으면 저장. Delete=마지막 점 지우기, ESC=작성 취소. 자기 교차·넓이 0인 도형은 저장하지 않는다. 상단바 '꼭짓점 이동/고정' 토글로 찍은 점과 저장한 도형의 꼭짓점을 끌어 옮긴다. 점 추가·삭제·이동·취소 모두 cmd+z 대상.
> - **면 단위:** polygon·multipolygon type에서 상단바 '점 단위/면 단위'로 전환. footprint는 면 단위 불가.
> - **선분 단위:** property type 레이어에서 개체를 골라 feature를 만드는 경로를 없앴다.
> - **진행률:** 다각형 막대 → 점 기준(전체 꼭짓점·교점 중 태깅된 점 + 제외된 점). 면으로 저장해도 점 기준.
> - **면 계산 방식 1~4 모두 반영:** ① `split()` 격자화(C5: 4.96초 → 0.033초, 조각 136,352·면 9,764개 동일) ② 층 불러올 때 면·점을 함께 만들어 재사용 ③ 레이어 생성·제외 변경 시 계산을 백그라운드로 ④ 파싱·색인과 면·점 계산의 캐시 열쇠 분리. 꼭짓점·교점 추출(`SnapPointExtractor`)도 격자화했다. 자세한 측정은 `01) 디버깅/04) 엔진 디버깅.md` 3장.
> - 개체 기준 진행률 막대(위쪽)는 그대로 두었다. 점으로 그린 도형은 개체를 소유하지 않아 이 막대를 움직이지 않는다 — 존치 여부 결정 필요.

- 원칙: 선분단위 작업은 이제 하지 않는다.
- 결정사항
	- 다각형 진행률 막대: 점 기준으로 바꿉니다. 전체 점의 수 중 제외/태깅 수를 봅니다. 이는 면 단위 선택을 혼용하더라도 점 기준을 유지합니다.
	- 깃헙 이슈는 이슈번호 # 21 을 확장합니다.
### 점단위 선택
- 점 선택 모드를 추가한다.
- 기존 SVG의 Vertex와 교점을 선택할 수 있게 한다.
    - 이 때, 기존 '문 임시로 닫기'기능에 있는 vertex 및 교점 선택 기능이 이미 있으므로 활용한다.
- 새 점을 추가할 수 있게 한다/
- 선택한 점을 순서대로 연결한다.
- 시작점(원점)을 마지막으로 선택하여 Polygon을 닫는다.
- 작성중인 DraftShape를 표시한다.
- ESC(escape)키로 작성중인 DraftShape를 취소한다.
- vetex 이동, 고정 모드를 추가한다.
- 점 추가/삭제/이동을 undo/redo (command + z / command + shift + z)에 포함한다.

	### 점 단위 선택 완료 조건

- 원본 SVG geometry가 닫혀 있지 않아도 새 DraftShape를 만들 수 있다.
- DraftShape가 원본 SVG object와 독립적으로 생성된다.
- 시작점 재선택으로 닫힌 polygon을 완성할 수 있다.
- vertex를 이동하거나 고정할 수 있다.
- 미완성 DraftShape는 feature로 확정되지 않는다.
- 자기 교차 DraftShape는 확정되지 않는다. (즉, 도형이 스스로 꼬이는 상황, 도형 내부 선분끼리 교차해서 x자로 크로스되는 상황은 경고가 떠야 함)

	### 면 단위 선택
	- property type이 polygon 또는 multipolygon인 경우에만 면 단위 선택이 가능하다
	- footprint는 면 단위 선택 대상에서 제외한다
	- 면 계산 방식
	1. **`split()`을 격자 방식으로 바꾼다.** 도면을 칸으로 나눠 같은 칸·이웃 칸의 선분끼리만 비교한다. 효과가 가장 크다. 몇 초 → 1초 미만을 기대하지만 **추정이고 아직 재지 않았다.**
	2. **면 목록을 재사용한다.** 층을 불러올 때 찾은 면을 캐시에 함께 보관하고, 레이어 생성 때 다시 계산하지 않는다.
	3. **메인 스레드에서 뺀다.** `rebuildClosedPolygons`·`rebuildVanishedPolygonCount`·`adopt`·`setRoutingDrawing`을 백그라운드로 옮긴다.
	4. **캐시 열쇠를 나눈다.** "SVG 파싱·색인"과 "면 계산"을 따로 캐시해, 제외 개체를 바꿔도 파싱부터 다시 하지 않게 한다.
