## 1. 보조 개체로 지정 기능
1. 똑같이 생긴 개체 모두 보기 - 누르면 커서가 로딩중 상태에서 돌아오지 않음. 
	- **(2026-08-25) 구현 완료 — 화면에서 눈으로 확인해 주시면 완료 처리합니다.**
	- **멈춘 게 아니라 정말로 계산 중이었다.** 무한 루프가 아니라 계산량 폭발이라, 기다리면 언젠가는 끝난다. 그래서 커서만 돌고 앱은 죽지 않았다.
	- **원인:** `VectorObject.twinKey`("똑같이 생긴" 판정용 키)는 **개체의 모든 점을 문자열로 이어 붙이는** 무거운 계산이다. 그런데 `twins(of:)`·`twinGroups`가 계산 프로퍼티라 부를 때마다 도면 **전체**의 키를 새로 만들었고, 캔버스는 `auxiliaryOpacity(for:)`를 **개체마다** 부르면서 그 안에서 또 `twins(of:)`를 불렀다. 결과가 **매 프레임 O(N² × 점 개수)**다.
	- 실측(디버그 빌드, 개체 600개 도면): 옛 방식이면 30프레임에 **약 100초**. 실도면은 개체가 수천 개라 제곱으로 더 늘어난다 — 사실상 안 돌아온다.
	- **고친 방식: 키는 도면이 바뀔 때만 바뀐다.** 도면을 적재하는 순간 인덱스(`개체→키`, `키→구성원`, 정렬된 그룹 목록)를 한 번 만들고, 이후에는 사전 조회만 한다. `document`의 `didSet`이 유일한 갱신 지점이다 — 다른 곳에서도 만들 수 있게 두면 "언제가 최신인가"가 흐려져 매 프레임 재계산으로 되돌아간다.
	- **캔버스는 강조 집합을 그리기 루프 *바깥*에서 한 번만 받는다**(`auxiliaryHighlightedIDs`). 개체마다 다시 물으면 개체 수만큼 집합을 새로 만들게 되어, 인덱스를 만들어 놓고도 같은 문제가 다시 난다.
	- 명세의 75% 수치는 `AuxiliaryOpacity`로 뷰에서 떼어냈다. 뷰 안에 박혀 있으면 `--selftest`가 확인할 방법이 없다.
	- 같은 계산을 쓰던 우측 쌍둥이 그룹 목록·'모든 보조 개체 제외'도 함께 빨라진다. 원인이 한 곳이라 고친 곳도 한 곳이다.
	- 검증: 빌드 통과, `--selftest` 306항목 전부 PASS(쌍둥이 인덱스 7항목 신규 — 적재 시 생성 / 그룹 수와 키 수 일치 / **캐시가 직접 계산과 일치** / 강조 꺼짐 시 100% / 75% 수치 / 큰 도면 인덱싱 / **600개 도면 30프레임 1초 이내**). 마지막 항목이 이번 건의 재발 방지선이다 — 고치기 전이라면 이 한 항목만으로 100초가 걸려 확실히 걸린다. 앱 번들 재빌드 완료.
2. 이제 로딩중 문제가 해결되었으니, 복수 선택 상태에서도 똑같이 생긴 개체 모두 보기 기능 지원.
	- **(2026-08-25) 구현 완료 — 화면에서 눈으로 확인해 주시면 완료 처리합니다.**
	- **이건 「뷰 디버깅」 11번을 뒤집는 결정이다.** 11번은 "둘 이상 선택하면 비활성화"였고, 근거는 "여럿을 고르면 서로 다른 쌍둥이 그룹이 섞여 100%로 뜨는 게 합집합이 되고, '무엇과 똑같은가'의 기준이 사라진다"였다. 그 근거 자체는 지금도 틀리지 않다 — **틀린 건 대응이었다.**
	- **왜 뒤집었나:** 실제 작업이 "치수 숫자 3종을 한꺼번에 골라 통째로 빼기"처럼 여러 그룹을 동시에 다루는 쪽이 훨씬 흔했다. 그런데 11번의 제약은 그때마다 그룹 하나씩 네 번 반복하게 만든다. 기준이 흐려지는 게 문제라면 **막을 게 아니라 기준을 화면에 띄우면 된다.**
	- **그래서 라벨이 몇 그룹의 합집합인지 말한다:** `쌍둥이 3그룹 · 24개 표시 중`. 그룹이 하나뿐이면 "1그룹"은 뜻 없는 숫자라 빼고 `쌍둥이 6개 표시 중`으로 쓴다. 도움말도 `선택한 2개가 걸친 쌍둥이 2그룹 전체를 100%로…`로 바꿔, 지금 100%인 게 무엇의 합인지가 버튼만 봐도 읽히게 했다.
	- 고친 것: `AppEnvironment.canShowTwins`가 `count == 1` → `!isEmpty`. **조건은 여전히 한 곳뿐이다** — 표시·지정·배율이 모두 이 하나를 본다(11번에서 정한 원칙 유지). 새로 만든 `selectedTwinGroupCount`(선택이 걸친 고유 키 수)가 그룹 수를 센다.
	- **자동 해제는 "선택이 0개가 될 때"로 좁혔다.** 11번에서 `didSet`에 건 자동 해제의 진짜 목적은 "켜져 있는데 끌 버튼이 없는 상태"를 막는 것이었다. 이제 2개여도 버튼이 살아 있으니 끌 방법은 있다. 선택이 **비면** 여전히 버튼이 사라지므로 그때만 끈다. 함정 자체가 없어진 게 아니라 발동 조건이 좁아진 것이라, `didSet`은 그대로 뒀다.
	- **버린 대안 — "여러 그룹이면 첫 그룹만 기준으로":** 기준이 하나로 유지돼 깔끔하지만, 사용자가 고른 3개 중 2개가 75%로 흐려진다. 자기가 방금 고른 게 흐려지는 건 고장으로 읽힌다.
	- 라벨 문구는 `TwinToggleText`(순수 함수)로 뷰에서 떼어냈다. `AuxiliaryOpacity`를 뺐던 이유와 같다 — 뷰 안에 문자열 보간으로 박혀 있으면 `--selftest`가 "그룹 수를 정말 보여주는가"를 확인할 방법이 없다. **화면이 사실을 말해 주는 게 이번 완화의 전제 조건이라, 그건 시험으로 못박아야 한다.**
	- 검증: 빌드 통과, `--selftest` 354항목 전부 PASS. 신규 11항목(선택 2개여도 활성 / 선택이 늘어도 효과 유지 / 섞인 선택은 그룹 수 2 / 여러 그룹은 합집합 / 합집합 전부 100% / 라벨 3항목 / 도움말 / 선택이 비면 꺼짐 / 배율 원복). 예전 "선택 2개면 비활성" 3항목은 **뒤집힌 결정이라 정반대 기대로 다시 썼고**, 되돌리려는 다음 세션이 먼저 보도록 시험 코드에 이유를 주석으로 남겼다.
3. 오른쪽 사이드바에서 똑같이 생긴 개체 그룹과, 개별 보조개체를 따로 볼 수 있도록 지원
	- **(2026-08-25) 구현 완료 — 화면에서 눈으로 확인해 주시면 완료 처리합니다.**
	- **원래 상태가 생각보다 나빴다.** 예전 목록 조건은 `twinGroups.filter { $0.count > 1 || 제외된 게 있으면 }` 하나뿐이라, **쌍둥이가 없는 개체는 아예 안 보였다.** 도면에 딱 하나뿐인 방위표·범례·제목 박스 같은 건 목록에서 찾을 방법이 없어 도면을 눈으로 훑어 클릭하는 수밖에 없었다. "따로 보고 싶다"가 아니라 "한쪽이 안 보인다"에 가까웠다.
	- **고른 방식: 세그먼트 전환**(`Picker` + `.segmented`). `똑같이 생긴 그룹 N` / `개별 개체 M` 두 탭.
	- **버린 대안 — 두 섹션을 위아래로 쌓기:** 만들기는 더 쉽지만, 개별 개체는 실도면에서 수백 개까지 늘어난다. 쌓으면 그 긴 목록이 쌍둥이 그룹 목록을 스크롤 밖으로 밀어낸다. 정작 작업량이 큰 쪽(반복이 많은 그룹)이 안 보이게 되는 셈이라 뒤집힌 우선순위다. 세그먼트는 한 번에 하나가 사이드바 전체 높이를 쓴다.
	- **탭 이름에 개수를 붙였다.** 보고 있지 않은 쪽의 규모를 알아야 "여기 없으면 저기 있겠구나"가 성립한다. 개수가 없으면 반대쪽 탭이 비었는지 안 봤는지 구별이 안 된다.
	- **두 목록은 겹치지 않고, 합치면 도면 전부다**(크기 2 이상 / 크기 1). 겹치게 두면 같은 개체가 두 탭에 나와 "이건 그룹인가 개별인가"가 흐려진다. 예전 조건의 `|| 제외된 게 있으면`은 뺐다 — 크기 1짜리를 그룹 탭에 끌어오려던 임시방편이었고, 이제 개별 탭이 제 자리를 준다. 제외된 개체를 되살리는 경로(행 클릭 → `지정 풀기`)는 개별 탭에서 그대로 된다.
	- **개별 개체용 강조 상태를 새로 만들지 않았다.** 크기 1짜리 그룹의 키는 그 개체 하나만 가리키므로 `focusedTwinKey` 하나로 두 탭이 다 된다. 따로 두면 강조 대상이 두 군데서 정해져 `auxiliaryHighlightedIDs`가 "둘 중 뭘 먼저 보나" 규칙을 또 만들어야 한다. 행 클릭 동작(그 대상만 100%, 나머지 75%)도 두 탭이 같은 코드다.
	- 목록을 나누는 판정은 뷰의 `filter`가 아니라 `AppEnvironment.auxiliarySidebarGroups(_:)`에 뒀다. **어느 개체가 어느 탭에 뜨는지는 판정 규칙이라 `--selftest`가 봐야 한다.** 뷰에 박아 두면 이번 같은 "한쪽이 통째로 안 보임"이 또 나도 못 잡는다.
	- 개별 탭에서는 `직선 × 1` 대신 모양 이름만, 제외 배지도 `1/1 제외` 대신 `제외됨`으로 쓴다. 하나뿐인 게 그 탭의 전제라 숫자가 뜻을 못 갖는다.
	- 검증: 빌드 통과, `--selftest` 354항목 전부 PASS. 신규 6항목(그룹 탭은 2개 이상만 / 개별 탭은 1개짜리만 / 두 탭이 안 겹침 / 합치면 전체 그룹 / **모든 개체가 어느 한 탭에는 뜬다** / 개별 개체도 단독 강조). 다섯 번째가 이번 건의 재발 방지선이다 — 예전 조건이라면 이 항목에서 걸린다.
4. 보조 개체 제외 창에서, '보조 개체로 지정' 또는 '똑같이 생긴 개체 모두 지정'을 하면 자동으로 기존 선택된 개체들이 선택 해제가 되도록 수정
	- **(2026-08-25) 구현 완료 — 화면에서 눈으로 확인해 주시면 완료 처리합니다.**
	- 둘 중 `markSelectedAsAuxiliary`('보조 개체로 지정')는 **이미 비우고 있었다.** 확인만 하고 그대로 뒀다. 실제로 남아 있던 건 `markTwinsAsAuxiliary`('똑같이 생긴 개체 모두 지정') 쪽이다.
	- **왜 비우나:** 지정은 이 창에서 **선택의 종착점**이다. 보조 개체로 지정하면 그 개체는 태깅 대상에서 빠지므로 더 할 일이 없다. 골라 둔 채 두면 다음 개체를 고를 때 이전 게 합쳐져, 화면의 `N개 선택`이 실제 작업 대상과 어긋난다.
	- **쌍둥이 쪽이 더 심하다.** 한 번에 그룹 전체가 나가므로 방금 지정한 수십 개가 통째로 남는다. 그 상태에서 다음 개체를 하나 더 고르면 선택이 수십 개짜리가 되고, 라벨의 그룹 수(1-2번)까지 같이 어긋난다.
	- **`지정 풀기`(`unmarkSelectedAsAuxiliary`)는 그대로 안 비운다.** 푼 개체를 이어서 다시 보거나 태깅하러 가는 흐름이 정상이라 선택이 남아 있어야 한다. 「아키텍쳐」 2.15-1절에 적혀 있던 기존 판단이고, 이번에도 유지했다. 종착점인 쪽만 비운다.
	- **`focusedTwinKey`는 일부러 안 건드린다.** 우측 목록에서 그룹을 지목해 들어온 흐름이면, 방금 무엇을 지정했는지가 화면에 100%로 남아 있어야 결과를 눈으로 확인할 수 있다. 선택(작업 대상)과 강조(보고 있는 대상)는 뜻이 다르다.
	- 선택이 비면 1-2번의 `didSet` 규칙이 그대로 작동해 `showTwinsOnly`도 같이 꺼진다. 따로 손댈 곳은 없었고 자체점검으로 못박았다.
	- 검증: 빌드 통과, `--selftest` 354항목 전부 PASS. 신규 3항목(지정 후 선택 자동 해제 / 선택이 비어 표시 효과도 함께 꺼짐 / **'지정 풀기'는 선택을 비우지 않는다**). 마지막 항목이 "그럼 전부 비우자"로 과잉 적용되는 걸 막는 선이다.

## 5. 개체 편집 기능

1. 점을 선택할 때, 한 개체 안에서 선택된 순서를 표시하도록 수정합니다. 예시: 1 - 2 - 3 ... // 이를 모든 레이어에 적용합니다.
2. 개체 편집 기능의 목표는, 이미 선택된 점 하나를 해당 개체에서 제거하고, 그 자리에 다른 점을 연결하게 하기 위함입니다. 현재처럼 선택한 순서대로만 이어지는 기존 방식은, 점을 중간에 지우고 다른 점을 선택했을 때 폴리곤이 꼬이거나 왜곡됩니다. 
3. control을 누른 채 이미 선택된 점을 다시 선택하면, 개체 편집 기능이 활성화됩니다. 이 점이 선분과 선분 사이의 점일 경우, 해당 점과 해당 점 이후 순번의 모든 점이 비활성화(흐릿하게 처리)됩니다. 예를 들어, 1 ... 4, 5, 6 일 때, 4번 점을 선택하면 4, 5, 6번 점까지 전부 흐릿하게 처리됩니다.
4. 계속 control을 누른 채로, 기존에 선택한 점이 아닌 다른 점을 선택한 후, 다시 기존에 선택한 점으로 돌아오면, 새로운 점이 순번에 편입되어 개체로 들어옵니다. 예를 들어, 4번 점을 제외하고 새로운 점 a를 선택하였을 경우, a가 새로이 4번 점이 됩니다.
5. 점을 제외하거나 교체하지 않고, 기존 점들에 더하여 새로운 점을 편입할 때도 마찬가지입니다. 1 ... 4, 5, 6까지 점이 있다고 할 때, 4번과 5번 사이에 새로운 점 a를 넣고 싶다면, control을 누른 채 4번 점을 선택하여 비활성화하고, 다시 4번 점을 눌러 활성화하고, a를 누르고, 5번 점을 눌러 폴리곤을 닫습니다.
6. 기존 점 - 새로운 점 - 기존 점이 연결되면 기비활성화된 모든 점들이 활성화됩니다. 이는 control을 떼어도 된다는 신호입니다. 
7. 선분이 중간에 끊긴 상태로도 control을 떼어 개체 편집 기능을 비활성화할 수 있습니다. 대신, property type이 polygon / multipolygon인 경우, 선택된 점들이 2개 이상의 선분일 경우 (=중간에 선분이 끊긴 경우) 경고 메시지를 띄웁니다.
