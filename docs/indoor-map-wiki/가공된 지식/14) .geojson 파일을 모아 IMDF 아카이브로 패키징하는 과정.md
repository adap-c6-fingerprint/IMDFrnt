# .geojson 파일을 모아 IMDF 아카이브로 패키징하는 과정

## 요약

IMDF는 "하나의 큰 파일"이 아니라 **Feature Type별 `.geojson` 파일 + `manifest.json`을 ZIP으로 묶은 아카이브**다. 이 문서는 그 마지막 묶는 단계, 즉 이미 만들어진 `.geojson` 파일들을 아카이브로 만드는 규칙을 다룬다. 앞 단계(도면에서 GeoJSON을 얻는 과정)는 [[02) 도면에서 GeoJSON(IMDF) 추출 전 과정]]에 있다.

중요한 점 하나: 확인한 OGC 표준 본문은 아카이브 확장자를 **`.zip`**으로 규정하며 `.imdf`는 나오지 않는다. IM-DFrnt 이슈 #38의 `.imdf`가 어떤 의미인지는 아래 "확인 필요" 참고.

## 핵심 내용

### 1. 아카이브 구성

| 구분 | 파일 | 비고 |
| --- | --- | --- |
| 필수 | `manifest.json`, `address.geojson`, `venue.geojson` | 하나라도 없으면 유효한 아카이브가 아님 |
| 선택 | `building`, `footprint`, `level`, `unit`, `opening`, `section`, `fixture`, `detail`, `amenity`, `anchor`, `occupant`, `kiosk`, `geofence`, `relationship` `.geojson` | 해당 Feature가 있을 때만 포함 |

각 `.geojson`은 같은 `feature_type`의 Feature만 담은 FeatureCollection이다. Feature Type 16종 정의는 [[08) IMDF Feature Type·카테고리 전체 레퍼런스]] 참고.

### 2. 패키징 단계

1. **수집** — 층별·타입별로 흩어진 `.geojson`을 Feature Type 기준으로 모은다. 같은 타입이 여러 층에 있으면 하나의 FeatureCollection `features` 배열로 합친다.
2. **필수 파일 확인** — `address`·`venue`가 없으면 패키징을 막고 사용자에게 알린다.
3. **참조 정합성 확인** — 각 Feature의 `id`는 UUID이며, `level_id`·`building_ids`·`venue_id` 같은 참조가 아카이브 안의 실제 Feature를 가리켜야 한다. 중복 `id`도 걸러야 한다.
4. **manifest 생성** — `version: "1.0.0"`, `created`(패키징 시점), `language`, 선택적으로 `generated_by`. 자세한 필드는 [[Manifest]] 참고.
5. **UTF-8 직렬화** — 각 JSON을 UTF-8로 쓴다.
6. **ZIP 압축** — 위 파일들을 ZIP 하나로 묶는다. 확장자는 표준상 `.zip`.
7. **검증** — [[IMDF Sandbox]]나 Apple 검증 엔진으로 구조·기하 규칙을 확인한다.

### 3. IM-DFrnt 현재 구현 상태 (2026-10-15 기준)

- 이슈 #38 `[Feat] .geojson 모아서 .imdf 변환 기능 추가`: 열려 있고, 본문은 목표 한 줄뿐이며 작업 목록·완료 조건이 템플릿 그대로다.
- `BuildingProject.imdfFiles()`(`Model/BuildingProject.swift`)가 이미 "타입별 파일 재구성"을 한다: `manifest.json`을 넣고, 전역 Feature(`globalGeoJSON`)와 층별 Feature(`levels[].geoJSON`)를 타입별 FeatureCollection으로 합쳐 `[파일명: JSON]` 딕셔너리를 만든다. 원본 Feature ID·속성·좌표와 collection의 추가 필드를 보존한다.
- `docs/projects/BUILDING_LEVELS.md`는 이 함수를 "후속 IMDF 내보내기 구현의 기반"이라 적고, **전체 IMDF ZIP 내보내기 UI는 이번 범위에 없다**고 명시한다.
- 불러오기 쪽(`Routing/IMDFImporter.swift`)은 ZIP·폴더·개별 JSON을 받는다. 즉 읽기는 있고 쓰기(ZIP 만들기)는 없다.
- 따라서 #38에 남은 일은 대략: 필수 파일 검사 → `imdfFiles()` 결과를 ZIP으로 쓰기 → 저장 UI. (구현 계획은 확정 전, 확인 필요)

### 4. 구현 시 주의할 점

- **좌표 0개 Feature도 포함한다.** Building·Occupant·Address는 geometry가 `null`이어도 아카이브에 들어간다 ([[09) IMDF에서 좌표를 갖는 것 전체]]).
- **원본 보존 필드를 버리지 않는다.** 불러온 IMDF의 unknown fields·collection header를 유지해야 왕복 시 데이터가 줄지 않는다.
- **`created`는 패키징 시점에 새로 만든다.** 불러온 manifest의 `created`를 그대로 두면 표준 취지와 어긋난다.
- **좌표는 WGS 84 경도·위도.** FME Writer도 쓸 때 WGS84로 재투영한다.

## 미해결 질문

- **확인 필요: `.imdf` 확장자의 출처.** 표준·FME 문서에는 없다. 사용자 용어(내부 이름 또는 `.zip` 별칭)인지, 별도 규격인지 의도 확인이 필요하다.
- ZIP 최상위에 파일을 둬야 하는지(하위 폴더 허용 여부) 표준 본문에 규정이 없다.
- Apple Maps Connect 업로드가 `.zip`만 받는지 확인하지 못했다.
- 불러온 IMDF와 새로 그린 Feature가 섞일 때 `venue`·`address`를 누가 만드는가(#19 건물 전역 정보 편집 기능과의 연결).
