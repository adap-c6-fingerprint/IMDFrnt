# 폴리곤화

## 요약

폴리곤화(polygonization)는 선분들의 집합을 **평면 그래프(planar graph)의 변**으로 보고, 그 선들이 둘러싼 **닫힌 면(face)**을 찾아 폴리곤으로 추출하는 연산이다. CAD 도면에서 벽 선분만 있고 방 도형은 없는 상태에서 "방"을 자동으로 만들어내는 단계가 바로 이것이다.

## 핵심 내용

- **입력 전제:** 선형이 위상적으로 깨끗해야 한다. FME `AreaBuilder` 공식 문서는 "Creates polygons from **topologically correct** linear features... creates areas wherever the linework **surrounds closed shapes**"라고 규정한다.
- **대표 실패 원인:** 교차점에서 끊기지 않은 선, 어긋난 노드, 오버슛/언더슛(선이 교차점을 지나치거나 못 미침), 교차점 노드 누락. 폴리곤이 되지 못한 선은 FME에서 `Incomplete` 포트로 빠진다.
- **노딩(noding) 선행:** 폴리곤화 전에 모든 교차점에서 선을 쪼개는 작업이 필요하다. Shapely 공식 문서는 `shapely.node`가 "a **fully-noded** linework suitable to [be] passed as input to polygonize"를 만든다고 설명한다.
- **허용 오차:** Esri ArcGIS Indoors는 "Endpoints must be within the configured xy tolerance range (**default 1mm**) to be considered as connected"를 기준으로 삼는다. 눈으로 붙어 보여도 이 오차를 넘으면 면이 닫히지 않는다.
- **구현체:** 상용은 [[FME]]의 `AreaBuilder`, 오픈소스는 Shapely의 `polygonize` / `polygonize_full`(진단 출력 포함)이 같은 알고리즘 계열이다.
- **실내 도면 특유의 문제:** 벽에 문이 뚫려 있으면 그 방은 위상적으로 닫히지 않는다. 그래서 폴리곤화 **전에 문 개구부를 임시로 막고**(Esri의 `CLOSE_DOORS`·`Door Close Buffer`), 폴리곤 확정 **후에 다시 열어** Opening 피처로 뽑는 이중 처리가 필요하다. 자세한 내용은 [[07) 도면의 방·문·창이 IMDF 좌표가 되는 기준]] 5.2~5.3절 참고.
- **한계:** 폴리곤화로 만들어낸 도형은 원본 CAD 엔티티와 1:1로 대응하지 않아 CAD 핸들 추적이 끊긴다. 도면 갱신 시 증분 반영 설계에 제약이 된다.

- 오버슛/언더슛 자동 보정(스냅핑) tolerance를 도면 축척·품질에 따라 어떻게 정하는가 — 실무 가이드 미확보.
- 폴리곤화 실패분(Incomplete)을 자동으로 복구하는 전략(선 연장, 최근접 끝점 연결 등)의 신뢰도는 어느 정도인가.
