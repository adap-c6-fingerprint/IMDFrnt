# 도면 축척

## 요약

도면 축척은 **도면 좌표 1단위가 실제 세계에서 몇 mm인가**를 말한다. 이 값이 있어야 물리 단위(mm)로 정의된 [[허용 오차]]를 도면 단위로 환산할 수 있다.

문제는 **도면 파일만 보고는 이 값을 알 수 없는 경우가 많다**는 것이다.

## 핵심 내용

### SVG viewBox는 무차원이다

- SVG `viewBox`의 값은 **무차원 사용자 단위(user unit)**다. 물리 치수 정보를 담지 않는다.
- 같은 `viewBox="0 0 1000 800"`이 20m짜리 사무실일 수도, 200m짜리 공항 터미널일 수도 있다.
- 따라서 축척을 모르는 상태에서 "이 틈은 7mm인가"라는 질문에 답할 수 없다.

### 축척을 얻는 경로

1. **`width`/`height` 속성의 물리 단위** — SVG 루트에 `width="500mm"`처럼 단위가 붙어 있으면 `viewBox` 값과의 비로 축척을 직접 계산할 수 있다. 다만 단위 없이 숫자만 있거나 `100%`인 경우도 흔하다.
2. **[[지오레퍼런싱]] 결과에서 유도** — [[어파인 변환]] 계수에서 도면 단위 1당 지상 거리를 뽑을 수 있다. 변환식 `lon = a·x + b·y + c`, `lat = d·x + e·y + f`에서 위도 φ일 때 x 방향 지상 거리는 대략 `√((a·111320·cosφ)² + (d·110540)²)`이다. 여기에 1000을 곱하면 도면 단위당 mm다.
3. **사용자 입력** — 도면에서 실제 거리를 아는 두 점을 찍고 그 거리를 입력받는다. 가장 확실하지만 사용자 손이 필요하다.

### 축척을 모를 때의 함정

- **도면 크기에 비례하는 허용 오차**는 축척을 모르는 문제를 해결하지 않고 **감춘다.** 어떤 도면에서든 그럴듯한 숫자를 내놓지만, 그 숫자가 물리적으로 무엇을 뜻하는지는 프로그램도 사용자도 모른다.
- 게다가 특정 규모에서 우연히 맞는 값을 내기 때문에 개발 중에는 문제가 드러나지 않는다.
- 축척을 끝내 알 수 없다면, 비례값을 쓰더라도 **"축척 미상 시의 임시값"임을 코드와 UI 양쪽에 명시**하고 그 상태의 판정 결과를 확정으로 다루지 않는 것이 옳다.
