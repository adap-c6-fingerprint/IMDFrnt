# 프레젠테이션 속성

## 요약

프레젠테이션 속성(presentation attribute)은 SVG에서 **CSS 속성명과 대응하는 XML 속성으로 스타일을 지정하는 방식**이다. `<rect fill="red" stroke-width="2">`의 `fill`·`stroke-width`가 그것이다.

파일을 눈으로 읽을 때 가장 먼저 보이는 형태지만, **캐스케이드에서는 최하위**다.

## 핵심 내용

### specificity 0

두 판본이 같은 결론을 명시한다.

> SVG 1.1 §6.4: "The presentation attributes thus will participate in the CSS2 cascade as if they were replaced by corresponding CSS style rules placed at the start of the author style sheet **with a specificity of zero.** In general, this means that the presentation attributes have **lower priority** than other CSS style rules"

> SVG 2 §6.6: "Presentation attributes contribute to the author level of the cascade, following all other author-level style sheets, and **have specificity 0.**"

SVG 2는 CSS2 §6.4.4 참조를 걷어내고 직접 서술로 문언을 바꿨을 뿐 결론은 같다.

### `!important`로 끌어올릴 수 없다

> "an !important declaration within a presentation attribute will cause it to have an **invalid value**."

값 자체가 무효가 되므로 우선순위를 높이는 탈출구가 없다.

### 실무적 함의

- **`<style>`의 타입 셀렉터 한 줄이 프레젠테이션 속성을 이긴다.** `rect { fill: red }`의 specificity는 (0,0,1)이고 프레젠테이션 속성은 0이다.
- 따라서 `<style>`을 읽지 않는 파서는 스타일을 "덜 반영"하는 것이 아니라 **정반대 색을 그린다.**
- 이 실패는 **조용하다.** 파싱 오류가 나지 않고 그럴듯하게 잘 그려지므로 사용자는 그것이 원본이라고 믿는다.

### 왜 최하위인가

프레젠테이션 속성은 CSS가 없던 시절부터 이어진 표현 수단이라, CSS 규칙이 이를 **덮어쓸 수 있어야** 나중에 스타일시트로 일괄 변경하는 것이 가능해진다. HTML의 `<font>` 같은 표현 태그를 CSS가 이기는 것과 같은 설계다. CSS-Tricks의 정리대로 "Presentation attributes are easier to override in CSS"인 것이 의도된 성질이다.

### 파싱 시 주의

- SVG 1.1 §6.8: 타입 셀렉터는 **local name**으로만 매칭한다 — "type selectors will only match against the local part of the element's qualified name."
- CSS 속성명은 대소문자를 구분하지 않지만 **값은 구분할 수 있다.** 입력 전체를 소문자화하면 색 키워드에는 안전하나 `url(#Gradient1)` 같은 참조에서 깨진다.
